项目工作台 - GitHub Pages 部署指南
==============================================

一、前置准备
==============================================

1. 注册 GitHub 账号：https://github.com/
2. 安装 Git：https://git-scm.com/

二、创建仓库
==============================================

1. 登录 GitHub
2. 点击右上角 "+" → "New repository"
3. 填写仓库信息：
   - Repository name: personalprojectplatform（或其他名称）
   - Description: 项目工作台 - 客户管理、订单管理、彩盒样机跟进
   - Public / Private: 根据需要选择
   - 不要勾选 "Initialize this repository with a README"

三、本地配置与推送
==============================================

打开命令提示符（CMD），执行以下命令：

1. 进入项目目录：
cd E:\项目管理

2. 初始化 Git 仓库（如果尚未初始化）：
git init

3. 配置用户名和邮箱：
git config user.name "你的用户名"
git config user.email "你的邮箱"

4. 添加所有文件：
git add .

5. 提交更改：
git commit -m "项目工作台完整代码"

6. 添加远程仓库（替换为你的仓库地址）：
git remote add origin https://github.com/你的用户名/personalprojectplatform.git

7. 推送代码：
git push -u origin main

四、配置 GitHub Pages（关键步骤）
==============================================

**方式一：使用 GitHub Actions 自动部署（推荐）**

1. 在 GitHub 仓库页面，点击 "Settings" → "Pages"
2. 在 "Source" 部分：
   - Branch: gh-pages（首次部署后会自动创建）
   - Folder: / (root)
3. 点击 "Save"

4. 启用 Actions 权限：
   - Settings → Actions → General
   - 在 "Workflow permissions" 中选择 "Read and write permissions"
   - 点击 "Save"

5. 推送代码后，GitHub Actions 会自动：
   - 安装依赖
   - 构建项目
   - 部署到 GitHub Pages

**方式二：手动部署（不推荐）**

1. 构建项目：
npm run build

2. 将 dist 目录内容推送到 gh-pages 分支：
git subtree push --prefix dist origin gh-pages

五、配置环境变量（生产环境）
==============================================

在 GitHub 仓库 → Settings → Secrets and variables → Actions → Variables 中添加：

- VITE_PROD_SUPABASE_URL: 你的 Supabase URL
- VITE_PROD_SUPABASE_ANON_KEY: 你的 Supabase 匿名密钥

六、访问地址
==============================================

部署成功后，访问地址为：
https://你的用户名.github.io/personalprojectplatform/

七、常见问题
==============================================

问题1：页面空白
原因：
- 没有构建就上传了源代码
- base 路径配置不正确

解决方案：
- 确保使用 GitHub Actions 自动构建部署
- 检查 vite.config.js 中的 base 配置是否正确

问题2：资源加载失败（404）
原因：base 路径与仓库名不一致
解决方案：
- 修改 vite.config.js 中的 base: '/仓库名/'
- 重新构建部署

问题3：Supabase 连接失败
原因：环境变量未配置
解决方案：
- 在 GitHub Actions 变量中配置 VITE_PROD_SUPABASE_URL 和 VITE_PROD_SUPABASE_ANON_KEY

问题4：Actions 部署失败
原因：权限不足
解决方案：
- 在 Settings → Actions → General 中启用 "Read and write permissions"

八、验证清单
==============================================

部署完成后验证：
- [ ] 访问页面正常显示登录界面
- [ ] CSS 样式正常加载
- [ ] JavaScript 功能正常
- [ ] Supabase 连接配置成功
- [ ] 业务数据正常显示
